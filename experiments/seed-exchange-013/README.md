# STATIC FIELD 013 — THE SEED EXCHANGE

**Status:** review-only, fictional, offline-first, independently governed experiments. The first functional Seed Exchange party surface is a *new Static Field source-owned adapter*, stacked on 012 World Garden → 011 World Breeder → 010 Living World Atlas → 009 Expansion Forge → 007 Railway. No original source owner is changed. No external mail server, wallet, NFT, authenticated identity, civic organization, real-world labor, wages, materials, railway or authority is generated.

## Why this is an exchange, not another catalogue

Four fictional party tables each **grow a complete original 012 garden game**. The 013 `prepareLot` checks original `GARDEN.verify`, independently issues an original **012 pollen packet** (`GARDEN.issuePacket`), and wraps that specific frozen packet in one typed thematic *interpretation* selected by the local fictional table: ROUTE, HARVEST, CARE or WITNESS. The native 012 issued content remains the previously supported DIGNITY×WITNESS / Witnessed Station; the four new motifs are 013 fictional interpretations, not claims that 012 already produced separate harvest/railway games.

Festival Table receives three separate packets by calling **original `GARDEN.act({type:'RECEIVE', packet})`**, and *independently* chooses to hold, refuse or locally admit each idea through **original `GARDEN.act({type:'MAIL_CHOICE', ...})`**. Only 2–4 distinct source owners already admitted may enter the 013 new game composer. Different source combinations generate **distinct ordered party-game requirements**: Shared Table, Harvest Express, Builder-Voice Route, Ledger Railway, Jubilee Caravan, or Commons Jubilee. These recipes are bounded, reviewed rule templates; **not executable code generation**.

Every originating source table must separately record a new Little Yes (or refuse); the Festival receiving host must separately choose ADMIT_LOCAL_GAME (or refuse). No event creates an authorized physical act. The new game is played as a finite ordered proposal/consent/planning/witness ritual, then may produce a content-integrity child-seed packet. Another table can hold, refuse or locally admit that child packet as **fictional reference only**. A new digest validates exact bytes, not identity, authorship, real-world facts or a human's consent. A genuine independent device currently transfers JSON through user action only. An arbitrary source card doesn't gain access to executable JavaScript.

## How to run

No dependencies beyond Node 22+ for tests; the self-contained HTML runs in browsers with Web Crypto secure context (file:// works in most modern browser environments; localhost is a fallback).

```bash
node --test \
  experiments/little-yes-field-008/rail/game.test.mjs \
  experiments/little-yes-field-008/kingdom/kingdom.test.mjs \
  experiments/expansion-forge-009/tests/forge.test.mjs \
  experiments/living-world-atlas-010/tests/atlas.test.mjs \
  experiments/world-breeder-011/tests/breeder.test.mjs \
  experiments/world-garden-012/tests/garden.test.mjs \
  experiments/seed-exchange-013/tests/exchange.test.mjs
node experiments/seed-exchange-013/build.mjs
node experiments/seed-exchange-013/proof.mjs
```

Open `experiments/seed-exchange-013/index.html` directly, or serve the directory over localhost if the browser disables file Web Crypto. Start empty and choose **Try suggested move** to grow three source-owned example gardens, post their seeds, independently admit at Festival Table, compose the Jubilee Caravan, record three source votes and host admission, play all five new stages, then export a baby-world postcard. Alternatively choose **Play the complete fictional festival**, then export the same result or save the replay-verified local history. The festival demo records **one receiving table's refusal and another's idea-only admission** of the finished child.

For an actual party, give different people the station cards and let them independently choose game decisions. This still does **not** turn the browser into a valid identity, authorization or real-world ledger system. The printable **Real-world question** is an *unsent, non-binding idea prompt*, never a dispatched volunteer work order or claim that a local organization consented.

## Source and destination boundaries

- The **original 012 source** confirms only a *local game state* when the demo prepares the source. Imported 013 seed packets contain the original 012 pollen JSON, whose original native schema and content hash are validated, but without a signed source snapshot they do **not** prove that a genuine source garden was run by anyone outside this demo. A malicious sender could re-create an unsigned fixture. No authentication is claimed.
- Original 012 receiver controls its local fictional HOLD / REFUSE / ADMIT_AS_FICTIONAL_REFERENCE. The 013 host and each sender control *separate additional* hypothetical votes. Physical inventory, consent and actual counterparty authority remain zero.
- The party game has a bounded six-recipe vocabulary and sequential storytelling actions, not a verified feasibility analysis, production plan, or authority-transfer mechanism. Full source 012 replay, 013 event replay, oversized file refusal, exact schema, source diversity, double decision and tamper testing are included.
- No automatic deployment, publication, group email, physical mail, blockchain, real money, child game recognition by First Bell/Wormhole Wars, or automatic Full Measure Deed. Parent worlds and original ledger are unchanged.
- Not yet tested on a real Android phone or with a human party; HTML generation and CLI tests are insufficient to claim visual usability or real-world readiness.
